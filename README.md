# stepwong

ZEPP Life API 刷微信支付宝步数

## ✨ 新功能

### Token 缓存机制（2026-01-14）
- ✅ 支持 Token 缓存，减少登录频率
- ✅ AES-128 加密存储，保护账号安全
- ✅ 自动复用有效 Token，降低风控风险
- ✅ 详细错误日志，便于问题排查

## 📦 快速开始

### 1. 安装依赖
```bash
pip install -r requirements.txt
```

### 2. 配置环境变量
在 GitHub Secrets 或本地环境中配置：

| 变量名 | 说明 | 必需 | 示例 |
|--------|------|------|------|
| `CONFIG` | 配置JSON | ✅ | 见下方说明 |
| `AES_KEY` | 16字节加密密钥 | ⭐ 推荐 | `1234567890abcdef` |

### 3. CONFIG 配置示例
```json
{
  "USER": "13800138000#user@example.com",
  "PWD": "password1#password2",
  "MIN_STEP": 18000,
  "MAX_STEP": 25000,
  "SLEEP_GAP": 5
}
```

## 🔐 Token 缓存配置

**强烈推荐**配置 `AES_KEY` 以启用 Token 缓存功能：

1. 生成 16 字节密钥（16 个字符）
2. 在 GitHub Secrets 中添加 `AES_KEY`
3. 首次运行后会自动生成 `encrypted_tokens.data` 文件
4. 后续运行将自动使用缓存的 Token

详细说明请查看：[Token 缓存功能文档](docs/TOKEN_CACHE.md)

## 🔧 接口返回 success 但步数不同步？

**现象**：日志显示 `修改步数（xxx）[success]`，但支付宝/微信运动步数没有变化，甚至 Zepp Life 账号被踢下线。

**原因**：华米对**从未绑定过手环/手表**的账号会判定为高风险账号，接口虽然返回成功，但会拦截步数同步到第三方平台。历史绑定过设备再解绑的账号属于"白名单"，不受影响。

**判断方法**：查看 Actions 日志

- `使用绑定设备ID:xxx` → 账号已绑定设备，正常
- `未查询到绑定设备，使用默认设备ID` → 账号没有绑定记录，**可能**被拦截（老号如有历史绑定记录也可能正常，以实际同步结果为准）

### 方案一：虚拟设备绑定（推荐，最快）

前往第三方站点 [https://bs.yanwan.store/run4/](https://bs.yanwan.store/run4/) 提交一次步数，该站点会自动为账号绑定一个虚拟设备。绑定成功后下次运行日志会显示 `使用绑定设备ID`，无需修改任何配置。

> ⚠️ 该站点为第三方服务，需输入 Zepp 账号密码，介意者请使用方案二。

### 方案二：真机绑定后解绑（最稳妥）

1. 准备一个小米手环/手表（1-7 代任意型号均可，二手即可）
2. Zepp Life → 我的 → 添加设备，完成绑定
3. 绑定成功后可立即解绑，账号已被华米标记为真实硬件用户

### 其他排查项

- **支付宝凌晨拒收**：支付宝在北京时间 00:00–07:00 拒收第三方提交的步数数据（微信无此限制），该时段刷的步数不会同步
- **重新绑定第三方**：Zepp Life → 我的 → 第三方接入 → 支付宝/微信，解绑后重新绑定
- **支付宝需实名**：未实名的支付宝账号有步数但无能量球
- **步数只增不减**：提交的步数小于当前值时无法覆盖
- **同步延迟**：接口成功后微信/支付宝可能有几秒到几分钟延迟，先看支付宝/微信再看 APP
